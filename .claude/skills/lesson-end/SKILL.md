# 세션 마무리 절차

다음 세션(다른 PC나 가벼운 모델일 수 있음)이 **문서만 보고 바로 이어갈 수 있게** 기록하는 것이 목적이다.

## 1. PROJECT_NOTES.md 갱신

1. 맨 위 `마지막 갱신:` 날짜
2. **"⭐ 현재 상태 한눈에"** 표: 현재 단계, 바로 다음 할 일 (다음 세션의 첫 스텝이 될 만큼 구체적으로), 배포 상태
3. **"세션 기록"** 맨 위에 새 항목 추가:
   ```
   ### YYYY-MM-DD — (한 줄 제목)
   - 한 일:
   - 배운 개념:
   - 막혔던 곳과 해결:
   - 다음 할 일:
   ```
4. 해당될 때만: "PC별 환경"(Godot 설치·경로), "위험 요소"(⬜ → ✅/❌), "🚗 차 테스트 기록", "👧👦 아이 관찰 기록", "결정 기록"(결정이 바뀌었을 때만 새 항목 추가)

## 2. ROADMAP.md 갱신

1. 끝낸 항목의 체크박스 `[ ]` → `[x]` (배우는 개념, 진행 순서, 완료 기준 모두)
2. Stage를 넘어갔다면 맨 위 `📍 현재 위치:` 줄 갱신
3. 오늘 새로 나온 용어를 §7 용어집에 한 줄씩 추가
4. 계획 자체가 바뀌었다면 (게임 규칙 확정 등) 해당 Stage 내용을 고친다

## 3. 사용자에게 요약 (짧게)

```
오늘 배운 것:
- (1)
- (2)
- (3)

다음 시간: (한 줄 예고)
```

## 4. git 커밋 제안

- `git status`로 바뀐 파일을 확인하고, 커밋 메시지 초안(영어 한 줄 + 필요하면 본문)을 보여 준 뒤 **사용자 승인 후** 커밋한다
- `godot/.godot/`, `export/`는 `.gitignore`로 제외되어 있다. `.import`, `.uid` 파일은 포함한다
- push는 사용자가 요청할 때만 한다
- 사용자가 git을 배우고 싶어 하면, 이 단계에서 `git status`, `git log`가 무엇을 보여 주는지 한 줄씩 설명한다

## 5. PC 전환 안내 (다른 PC로 옮길 예정이면)

"Godot을 닫고 → OneDrive가 초록 체크(동기화 완료)인지 확인한 뒤 다른 PC에서 여세요" 한 줄
